# Report Question-Driven（问题驱动式报告生成）

## 为什么是问题驱动，而不是内容陈列

内容陈列式报告（❌）：
> 0. 一页摘要 → 1. 背景 → 2. 市场 → 3. 竞品 → 4. 痛点 → 5. 建议

读者被动接收列表，读完就忘，抓不住重点，也无法判断"这些和我有什么关系"。

问题驱动式报告（✅）：
> 0. 你要回答的问题（先看这里）→ 1. Q1：市场够大吗？→ 2. Q2：竞品做到哪了？→ 3. Q3：家长为什么买单？→ N. 回到问题：哪些答了、哪些没答、下一步该问什么

读者带着自己的问题读，脑子在"挖答案"，读完能回答最初的问题、能做出决定。**报告是寻宝图，不是陈列柜。**

## 铁律（违反任意一条即为不合格）

1. **第一屏必须是问题清单**，不是摘要、不是背景、不是调研方法。摘要只在问题之后以"一句话回答"出现。
2. **章节标题必须是问句或决策问题**，禁止"市场情况""竞品分析""用户痛点"这类陈列式标题。
3. **每个结论必须回答一个明确的问题**；答非所问的内容删除。
4. **每个答案必须有证据支撑**（来源、Operation/Artifact 引用、可信度）；证据不足就写"未验证/平台失败"，不猜测。
5. **结尾必须回到开头的问题**：哪些已答、哪些未答、又引出了什么新问题。

## 第一步：问题优先（写报告前，先只写问题）

1. 收集读者真正关心的问题：决策问题（"我该不该做？""从哪切入？"）、疑问（"为什么没人做好？"）、反直觉点（"市场在涨为什么销量在跌？"）。
2. 用**读者会问出口的话**写问题，口语化、具体、可回答。禁止术语包装（"K12 个性化教育的市场结构如何" → "这个市场够大吗？"）。
3. 数量控制在 **3-10 个**，按决策重要性排序。写不出来 3 个问题 = 还没想清楚这份报告为什么存在。
4. 每个问题标注"谁在问"（读者自己/老板/潜在用户）和"答完能做什么决定"。

## 第二步：问题树（把问题拆成证据路径）

```
Q1（主问题）── Q1a 数据有多大？
            └─ Q1b 增长是不是真的？
            └─ Q1c 政策是推还是堵？
```
- 每个叶子问题对应一组证据（已采集的 Operation/Artifact，或待补采的缺口）。
- 先画树，再写正文。正文顺序 = 读者顺着问题挖答案的顺序，**不是采集顺序**。

## 第三步：Q-A 章节（每章四件套）

```
## Q3：家长为什么会买一台 9000 块的学习机？

**证据**（先给证据，让读者自己先想）：
- [来源] 多鲸报告：学习机市场 691 亿；艾媒：40% 可接受 2000-4000 元
- [来源] 小红书：科大讯飞"避雷"、搜狐：45% 用户只用拍照搜题

**你先想想**（可选留白）：如果是你，你会因为什么功能付 9000 块？

**答案**：家长买的不是 AI 功能，是"有人管孩子"（监督+规划）——证据显示高价 AI 功能使用率极低。

**未决点**：这是推断，缺乏对真实购买决策的一手访谈证据（缺口）。
```

- **证据先于答案**：读者先接触原始材料，再对照答案，挖掘感最强。
- "你先想想"是可选的设计：在关键反直觉结论前留白，让读者先形成自己的判断。
- 每章结尾用一句话指向下一个问题："既然买的是'有人管孩子'，那 Q4：现有产品为什么没管好？"

## 第四步：证据闭环

- 每个答案标注证据：来源名、Operation/Artifact ID（`collector://operations/...`）、可信度级别。
- 可信度分级随报告附上（A 权威机构 / B 主流媒体 / C 真实用户 / D 营销软广）。
- 平台失败如实写：`stopped`/`partial` 就写"该平台此路未采到"，不写"无结果"。

## 第五步：结尾回到问题

- 表格回放开头问题：✅已答 / ⚠️部分 / ❌未答。
- 未答问题 = 下一步调研清单，而不是"后续建议"的客套。
- 最后一句给读者一个新问题（推动下一步行动），而不是"总结"。

## 参考示例（必读）

- **完整优秀示例**：`references/example-report.md`。
- 这是本 Skill 的**黄金参考报告**，来自一次真实 K12 苏格拉底式 AI 学习产品调研；它完整展示了问题驱动式报告应该长什么样。
- **写任何报告前必须先读这份示例**，并对照检查自己的报告是否具备同样的结构：
  1. 开头有“读者 / 读完能做什么决定 / 配套证据”；
  2. 第 0 节是问题清单表格（谁在问、答完能做什么决定）；
  3. 每个章节是 Q-A 四件套：证据 → 你先想想 → 答案 → 下一个问题；
  4. 证据带来源与可信度分级；
  5. 结尾“回到问题”表格标注 ✅/⚠️/❌，并把未决问题写成下一步调研清单。
- **不要照抄内容**：示例的行业、数据、结论只用于展示结构和写作密度；每次必须替换成本次委托的真实证据、真实读者问题和真实结论。
- 如果最终报告比这份示例更短、更空、更陈列化，视为不合格，必须按示例结构重写。

## 与其他 Skill 的衔接

- 证据采集用 `$research-search-then-detail`（先广度后深度，严格串行，原始数据落盘）。
- 报告与证据分离：`report.md` 只写问题-答案-证据链；`evidence-ledger.md` 保存全部 Operation 台账与原始素材摘要；`data/raw/` 保存原始 JSON。**问题驱动的是报告，不是台账——台账就该是陈列。**
- 本 Skill 不调用任何 MCP 工具，它只规定"把证据组织成报告"的方法。

### ✅ 问题驱动式（改造后）
```
# 把"苏格拉底式 AI 学习"搬进 K12，值不值得做？

> 写给想验证这个方向的人。读完你能回答：做不做、从哪切、怕什么。

## 0. 你要回答的问题
- Q1 这个市场够大吗？（你：判断值不值得投入）
- Q2 现有玩家做到哪了？为什么"个性化"还没人做好？（你：找空档）
- Q3 家长到底为什么买单？（你：设计付费点）
- Q4 破卷的方法能直接搬吗？不能的话差在哪？（你：定改造清单）
- Q5 最大的风险是什么？（你：决定要不要继续）

## 1. Q1：这个市场够大吗？
**证据**：……（先给数据）
**你先想想**：千亿市场里 42% 是"个性化学习平台"，为什么还没出现赢家？
**答案**：够大，且个性化是最大增量；但"量降价升"说明靠涨价撑着。
**下一个问题**：既然够大，Q2：为什么头部玩家没做透？

## 2. Q2：……
（……）

## 6. 回到问题
| 问题 | 状态 |
|---|---|
| Q1 市场够大吗 | ✅ 够大（380 亿/42% 增量） |
| Q2 为什么没人做好 | ✅ 都停在"测-推-讲"，没人做教学法层 |
| Q3 家长为什么买单 | ⚠️ 推断"有人管孩子"，缺一手访谈 |
| Q4 破卷能直接搬吗 | ✅ 不能，差在双用户模型/课标/合规 |

**下一步该问的问题**：家长对"引导式 AI（不直接给答案）"的接受度到底多高？——先访谈 5-8 个家庭再定 MVP。
```
